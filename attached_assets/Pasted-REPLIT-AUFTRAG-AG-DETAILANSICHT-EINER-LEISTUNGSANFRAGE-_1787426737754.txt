REPLIT-AUFTRAG – AG-DETAILANSICHT EINER LEISTUNGSANFRAGE VOLLSTÄNDIG NEU AUFBAUEN

Arbeite im aktuellen Replit-Codebestand.

Replit ist die maßgebliche Arbeitsumgebung. Git dient der Veröffentlichung und externen Prüfung.

ZIEL DIESES AUFTRAGS:

Die Detailansicht einer Leistungsanfrage auf Seiten des AG soll vollständig neu strukturiert und deutlich einfacher bedienbar werden.

Die neue Ansicht soll:

1. sofort zeigen, was der AG aktuell tun muss,
2. die aktuelle Abstimmung verständlich darstellen,
3. die ursprüngliche Leistungsanfrage vollständig zugänglich machen,
4. Risiken, Klärungen und Bereitschaft kompakt darstellen,
5. genau einen fachlichen Verlauf besitzen,
6. alle bisherigen fachlichen und technischen Detailinformationen weiterhin zugänglich machen,
7. auf kleinen Displays vollständig bedienbar sein,
8. keine alte parallele AG-Detailansicht mehr verfügbar lassen.

WICHTIG:

Es sollen KEINE fachlichen Informationen verloren gehen.

Das Ziel ist NICHT:
„weniger Informationen“.

Das Ziel ist:

„weniger Informationen gleichzeitig sichtbar, aber alle Informationen gezielt abrufbar“.

Die neue Seite verwendet deshalb konsequent:

Übersicht
→ aufklappbare fachliche Details
→ technische Details

Die größere AN-Detailansicht ist NICHT Bestandteil dieses Auftrags.

Gemeinsam genutzte Komponenten dürfen nur verändert werden, wenn dadurch die AN-Seite nicht unbeabsichtigt verändert oder beschädigt wird.

============================================================
1. KANONISCHE AG-DETAILSEITE FESTLEGEN
============================================================

Es darf nach Abschluss genau EINE kanonische Detailansicht für eine AG-Leistungsanfrage geben.

Prüfe zunächst alle aktuellen AG-Routen und Detailseiten.

Insbesondere suchen nach Dateien und Komponenten wie:

artifacts/ag-app/src/pages/leistungsanfragen-detail.tsx
artifacts/ag-app/src/pages/takt-request-detail.tsx

sowie weiteren vollständigen Detailseiten derselben Leistungsanfrage.

Die aktuelle produktive Route für „Leistungsanfrage öffnen“ soll auf genau eine kanonische Seite zeigen.

Bevorzugt die aktuelle:

leistungsanfragen-detail.tsx

als kanonische Seite weiterverwenden und vollständig refaktorieren.

Keine zusätzliche neue parallele Detailseite erzeugen.


============================================================
2. ALTE AG-DETAILANSICHTEN MÜSSEN DANACH NICHT MEHR VERFÜGBAR SEIN
============================================================

Dies ist eine verbindliche Anforderung.

Nach Abschluss darf keine alte AG-Detailansicht mehr über:

- Navigation
- Listen
- Dashboard
- Coordination Board
- „Meine Aufgaben“
- Browser-Direkt-URL
- alte Route
- alte Legacy-Route

erreichbar sein.


------------------------------------------------------------
2.1 ALTE DETAILSEITEN PRÜFEN
------------------------------------------------------------

Global suchen nach:

takt-request-detail
leistungsanfragen-detail
request-detail

und allen AG-Routen, die Request-Detailseiten rendern.

Für jede alte vollständige AG-Detailseite entscheiden:

A) vollständig ungenutzt:
→ Datei löschen.

B) alte Route existiert noch:
→ alte Route auf die kanonische neue AG-Detailroute umleiten.

C) alte Seite wird noch von einer Route importiert:
→ Route auf kanonische Detailseite umstellen
→ alten Import entfernen
→ alte Seite löschen.


------------------------------------------------------------
2.2 KEINE ALTE SEITE HINTER LEGACY-URL RENDERN
------------------------------------------------------------

Wenn aus Kompatibilitätsgründen eine alte URL erhalten bleiben muss:

NICHT die alte Detailseite rendern.

Stattdessen:

legacy route
→ Redirect zur kanonischen AG-Detailroute

Dabei Request-ID übernehmen.

Beispiel sinngemäß:

/ag/takt-requests/:id
→ redirect
/ag/leistungsanfragen/:id

Die tatsächlichen vorhandenen Routes verwenden.

Keine neue URL-Struktur erfinden, wenn bereits eine kanonische Route existiert.

------------------------------------------------------------

Keine alten Seiten als „Reserve“ im Source Tree behalten.
