GESAMTAUFTRAG – VOLLSTÄNDIGE DURCHGÄNGIGE END-TO-END-TESTS FÜR AG-/AN-PROJEKT-, LEISTUNGS- UND ÄNDERUNGSKOORDINATION

ZIEL

Es sollen vollständige automatisierte End-to-End-Geschäftsprozesse implementiert werden.

Die Tests dürfen nicht nur einzelne Endpunkte oder Funktionen isoliert prüfen.

Sie sollen den tatsächlichen Ablauf zwischen:

AG
→ DataspaceExchange
→ AN
→ DataspaceExchange
→ AG

durchgängig abbilden.

Dabei müssen sowohl:

- Benutzeroberfläche
- fachliche Zustände
- API
- Outbox
- DataspaceExchange
- Inbound Processing
- Idempotenz
- Datensouveränität
- Ressourcenplanung
- Alternativen
- Änderungsprozesse
- Fehler- und Retry-Fälle

geprüft werden.


======================================================================
0. VERBINDLICHE BENUTZERFÜHRUNG DES AN
======================================================================

Für sämtliche E2E-Tests gilt folgende fachliche Zuordnung der AN-Oberfläche.


DASHBOARD

Das Dashboard ist ausschließlich eine Übersicht.

Es darf beispielsweise anzeigen:

- Anzahl offener Anfragen
- bevorstehende Termine
- Hinweise auf offene Entscheidungen
- Kennzahlen
- Statusinformationen

Das Dashboard ist NICHT die primäre Bearbeitungsseite.


ANFRAGEN

„Anfragen“ ist die zentrale Inbox und Bearbeitungsseite für Vorgänge, auf die der AN reagieren muss.

Dort erscheinen insbesondere:

- Projekteinladungen
- Leistungsanfragen
- Auswahl einer zuvor vorgeschlagenen Alternative
- Änderungsanfragen des AG
- Ergebnisse bzw. Antworten auf eigene Änderungsvorschläge
- gegebenenfalls Klärungsanfragen

Hier werden fachliche Entscheidungen getroffen.


TERMINÜBERSICHT

Die Terminübersicht zeigt den terminlichen Gesamtstand.

Dort erscheinen insbesondere:

- angenommene gemeinsame Projekte
- Leistungen
- aktuell vereinbarte Zeiträume
- bestätigte Änderungen
- bevorstehende Leistungen
- terminliche Gesamtübersicht

Die Terminübersicht ist NICHT die primäre Inbox für neue Anfragen.


RESSOURCEN

„Ressourcen“ enthält ausschließlich die interne AN-Planung.

Dort erfolgen beispielsweise:

- Ressourcenbedarf
- Ressourcenanlage
- Ressourcenbelegung
- Verfügbarkeitsprüfung
- Kapazitätsprüfung
- interne Planung
- gegebenenfalls Gesamtbelegung

Diese Informationen sind AN-intern.


EINSTELLUNGEN

Für die fachlichen E2E-Geschäftsprozesse grundsätzlich nicht relevant.


DATENRAUM

Es gibt keinen notwendigen sichtbaren Menüpunkt „Datenraum“.

Der Datenraum arbeitet als technische Infrastruktur im Hintergrund.


======================================================================
1. VERBINDLICHER ARCHITEKTURGRUNDSATZ
======================================================================

AG_DATABASE_URL
AN_DATABASE_URL
HUB_DATABASE_URL

bleiben als getrennte Connection-Kontexte bestehen.

Im aktuellen PoC dürfen alle drei URLs:

- auf dieselbe PostgreSQL-Datenbank
- mit demselben PostgreSQL-Benutzer

zeigen.

Die drei Connections stellen deshalb aktuell KEINE physische Sicherheitsgrenze dar.

Die Tests müssen beweisen, dass trotzdem keine direkte fachliche Kommunikation durch gemeinsame Datenbank-Rows erfolgt.


Organisationsübergreifender Übergang:

lokaler Zustand Sender
→ Transactional Outbox
→ DataspaceExchange
→ Inbound Processor
→ lokale Sicht Empfänger


Verboten:

AG schreibt Datensatz
→ AN liest denselben privaten Datensatz direkt aus gemeinsamer DB

oder:

AN ändert Datensatz
→ AG sieht dieselbe Row sofort

======================================================================

Die E2E-Suite ist erst abgeschlossen, wenn:

1. AG ein Projekt anlegen kann.

2. AG einen verifizierten AN einladen kann.

3. Die Einladung beim AN erst nach Dataspace-Inbound unter „Anfragen“ erscheint.

4. AN die Projekteinladung unter „Anfragen“ akzeptieren kann.

5. AG Membership erst nach Response-Inbound ACTIVE wird.

6. AG anschließend eine Leistung definieren kann.

7. AG die Leistung ausschließlich einem ACTIVE Projektpartner zuweisen kann.

8. Kein ACTIVE project_contractors Datensatz zusätzlich erforderlich ist.

9. Die Leistungsanfrage beim AN erst nach Dataspace-Inbound unter „Anfragen“ erscheint.

10. AN aus der Leistungsanfrage zu „Ressourcen“ wechseln kann.

11. Der Zusammenhang mit der Leistungsanfrage beim Wechsel erhalten bleibt.

12. AN Ressourcenbedarf erfassen kann.

13. AN Ressourcen anlegen bzw. auswählen kann.

14. AN Ressourcenbelegungen prüfen kann.

15. AG keinen direkten Zugriff auf diese Ressourcen erhält.

16. AN den ursprünglichen Leistungszeitraum ablehnen kann.

17. AN mindestens zwei Alternativen übermitteln kann.

18. AG beide Alternativen sehen kann.

19. AG eine Alternative auswählen kann.

20. Die Auswahl beim AN erst nach Dataspace-Inbound erscheint.

21. AN die ausgewählte Alternative erneut intern prüfen kann.

22. AN die Alternative final bestätigen kann.

23. Beide Seiten danach denselben vereinbarten Zeitraum besitzen.

24. Die Terminübersicht beim AN den finalen Stand korrekt zeigt.

25. Das Dashboard nur als Übersicht funktioniert.

26. „Anfragen“ die zentrale Inbox für handlungsrelevante Vorgänge ist.

27. „Ressourcen“ die interne AN-Planung enthält.

28. Eine nachträgliche Änderung durch AG vollständig funktioniert.
